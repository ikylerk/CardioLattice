# 临床边界与安全

[English](clinical-boundaries.md)

> **研究原型，不是医疗器械。** 本项目未取得 NMPA / FDA / CE 认证，输出不得用于临床诊断、治疗决策或医疗法律用途。演示模式中的数据全部为程序化合成数据。

## 已实现的软件与验证状态

截至 2026-10-20 整合，已实现 DICOM/NIfTI 导入、原始标签几何、参考解剖、研究配准、纵向对比、AI 报告接口以及报告修订/批准流程。合成已知答案测试和 mock SDK/模型调用验证的是软件契约，不是外部精度研究或临床验证。本环境验收尚未接入真实 AI API key，真实云调用及模型权重推理仍未验证。

## 1. 人工复核与报告完整性

- 测量记录 `method`、`source`、`validationStatus` 和来源追溯信息。
- 模板和 AI 报告均从草稿开始。已实现证据/数字核查及 `needs_review` 门禁；未解决的复核标记会阻止批准。
- 编辑、修订、恢复和批准追加报告版本。批准必须携带 `baseVersion` 和 `baseContentHash`，过期提交被拒绝。编辑及 AI 重生成清除当前批准。
- SHA-256 `contentHash` 标识报告正文；批准绑定所复核的版本和哈希，并记录操作者/时间审计事件。哈希不是数字签名，研究用途的操作者标签也不是经过认证的医生身份。
- 历史保留限于报告工作流。流水线重跑可能替换派生报告，不能声称永久归档或防篡改存储。
- 创建任务/草稿时记录 `lang=en|zh`，保存于 `content.lang` 和 `content.provenance.lang`；读取不翻译、不改写正文。API 状态和标签消息采用稳定代码。

参见[报告版本与批准契约](report-version-review-handoff.md)和[AI 报告](ai-reporting.md)。

## 2. 哪些可以计算，哪些不能

| 输出 | 当前状态 | 依据 / 限制 |
| --- | --- | --- |
| 心腔或所提供标签的体积 | 已实现研究测量 | 体素数 × 体素体积；比较时必须明确采集时相 |
| 公开 NIfTI 标签体积及冠脉 mask 分析 | 已在原始标签网格实现 | 保留原始几何与哈希；显示降采样不决定测量网格 |
| DICOM 模型派生体积 | 在其分割网格实现 | 不声称所有输入路径均完成原生定量 |
| 冠脉长度、分支和管径摘要 | 描述性研究输出 | 每个原始分量须保留连通骨架；显示中心线/管径覆盖最长路径，不是完整临床 QCA |
| 左心室心肌质量 | 无已验证输出 | 心肌标签与假定密度本身不足以建立有效测量 |
| EDV / ESV / EF / SV | 不能由单时相 CTA 得出 | 需要适当的舒张末期/收缩末期数据 |
| Agatston 钙化积分 | 不能由增强 CCTA 得出 | 需要非增强钙化积分序列 |
| 主动脉 / 肺动脉直径 | 仍需实现和验证 | 需要合适的中心线与垂直截面 |
| 狭窄百分比 / MLA / FFR-CT | 不提供已验证输出 | 需要有效的管腔/压力模型与独立参照测量 |
| AHA 灌注/存活心肌、SYNTAX / MACE 风险 | 未计算 | 缺少所需数据与经过验证的模型 |
| 纵向对比 | 已实现研究流程 | 同一受试者、有效且有序的检查日期、配准质控与测量可比性门禁；失败则抑制差值 |
| 个体事件预测 | 未实现 | 对比不等于预测 |

无效、空白或未映射解剖语义的 mask 不能建立成功配准。冠脉骨架分量消失或断裂会明确失败，不能输出部分成功的分析。参见[影像几何](imaging-geometry.md)和[对比契约](longitudinal-comparison.md)。

## 3. 参考图谱、坐标和配准

器官库包含 **19 个参考器官**、命名细部结构和 **109 个参考靶点**，改编自 BodyParts3D 4.0 与 HuBMAP HRA v1.1。它们不是患者解剖或病灶。患者网格来自提供或模型生成的患者 mask，并记录自身来源。`HEART_LV` 等内部编码不是经认证的 SNOMED/RadLex/FMA 绑定。`GET /api/organs` 提供稳定标识和 `code`/`params` 显示字段；打包目录仍保留前端显示名称。

患者影像元数据使用 **LPS 物理毫米坐标**，参考库使用 **RAS_ORGAN_REFERENCE**。RAS 数组轴排列不会把 SITK 物理元数据转换成 RAS。患者预览中心坐标是另一显示坐标系：`center_mm = (dims - 1) * spacing / 2`。这些坐标系之间必须显式变换，不能互相替代。

心脏图谱配准已实现基于显式心腔语义的研究相似变换，并区分真实观测标志点与映射参考点。缺失/重复标签、退化几何均按失败处理。心腔标志点 RMS 是样本内拟合残差，**不是靶点精度**；`targetAccuracyStatus` 保持 `not_evaluated`。显示的映射靶点仍是参考靶点。参见[配准契约](atlas-registration.md)。

参考靶点模拟支持靶点、入路方向、进针/深度动画、裁切平面和简单射线/表面相交。它不模拟组织形变、呼吸或经过验证的安全余量，不是手术导航、活检/消融规划或机器人引导，不得指导真实操作。

## 4. 模型治理与许可

研究计算可带研究状态展示；未支持的临床输出保持 `not_computed`。临床使用仍需独立完成模型/版本/权重追溯、任务许可、外部验证、稳健性评价、模型卡及适用的审查流程。

TotalSegmentator 可选适配器需要显式选择，检查支持的输出名称与非空 mask，保留物理几何，并记录实际安装包版本；该版本不是已核验的权重版本。mock 调用加真实 NIfTI 文件仅验证适配契约。TotalSegmentator 代码为 Apache-2.0，官方将 `heartchambers_highres`、`coronary_arteries` 列为需要许可的任务，须遵循[官方任务许可要求](https://github.com/wasserth/TotalSegmentator#subtasks)，不能由软件许可推导商用权利。

ASOCA/ImageCAS 导入不代表来源已验证或拥有再分发权；应保存实际来源并遵守具体分发协议。参考器官外形、细部及派生靶点保留 CC BY 4.0 署名，独立于仓库代码的 MIT 许可，见[完整署名](../src/assets/organs/ATTRIBUTION.zh-CN.md)。

## 5. 数据治理与监管状态

- 可识别患者数据需要获批方案、伦理/IRB 审查和数据使用协议，本原型不提供这些治理授权。
- 去标识会移除常见 PHI 标签并重映射 UID，但不能可靠移除像素内烧录标注，仍需操作者复核。
- 原始上传保留以便重处理。共享部署需要保留/删除规则、访问控制、备份和审计复核。
- 日志不得包含 PHI 或原始 DICOM 标签。

临床部署需要独立的软件生命周期、风险管理、临床评价与适用监管流程。测试通过、报告批准或研究质控通过均不构成认证或临床安全证明。中文报告完整保留本文开头的免责声明，英文报告保留[英文版](clinical-boundaries.md)的完整英文原文，互不替代或缩短。
