# 路线图

[English](roadmap.md)

## M1 — 真实数据链路（当前）

- DICOM 上传、安全解压、序列评分与选择。
- PHI 去除、UID 重映射、HU 解码、LPS→RAS、各向同性重采样。
- 预览体数据 + 任意 dims/spacing/huRange 的 MPR/VRT。
- 合成真值分割、marching cubes、GLB 导出。
- 确定性心腔容积测量和模板报告草稿。
- 检查工作台、患者三维视图、可追溯分析视图、结构化报告。
- 审计哈希链、报告批准、删除。
- 后端测试与 Playwright 端到端测试；保留离线演示构建。

## M2 — 真实分割与 AI 辅助报告

- 接入固定版本的 TotalSegmentator，并保存标签图快照。
- Claude 只根据结构化事实起草报告，并具备：
  - 严格的 JSON schema；
  - 每条数值结论都有证据引用；
  - 数值与测量交叉核对；
  - API 不可用时回退到模板；
  - 医生接受/编辑/拒绝，以及不可变的报告版本。
- 报告编辑界面、PDF 导出、报告对比。
- 模型注册表和按任务的许可核对。

## M3 — 纵向对比

- 按假名化受试者选择既往检查。
- 刚体/仿射配准，并给出质量指标（Dice、质心距离、变换幅度）；低质量配准必须人工复核。
- 带可比性警告的 delta 指标（层厚、重建核、kV、对比剂时相、模型版本）。
- 界面命名为「纵向对比」，而不是「预测」。

## M4 — 冠脉 AI

- 专用的冠脉管腔/狭窄模型（例如在 ImageCAS 上训练/验证），置于研究开关之后。
- 中心线提取、横截面管腔测量、斑块特征描述。
- 独立验证：Dice/HD95、狭窄与 QCA 的一致性、外部测试集、失败分析。
- 仅在求解器经过验证后，才可选地做 FFR-CT 研究集成。

## M5 — 生产加固

- OIDC/RBAC、审计导出、保留任务。
- Postgres、S3 兼容存储、Redis/RQ worker、GPU 推理 worker。
- 监控、备份、灾难恢复、渗透测试。
- 临床安全评审、数据保护评估、监管规划。

## 在验证完成之前明确不做

- 自主诊断；
- 由未经验证的模型给出的狭窄百分比；
- 单时相 EF；
- 仅凭解剖计算 FFR-CT；
- 个体事件预测；
- 未经治理批准的真实患者数据。
